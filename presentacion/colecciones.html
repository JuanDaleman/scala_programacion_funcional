¿Qué incluye la cotización?

La tienda ofrece un 10 % de descuento. Cotiza una unidad de cada producto disponible.

La cotización debe mostrar el nombre y el precio final de cada producto incluido, más el total.

Primera solución · Un bucle imperativo

El mismo for decide qué incluir, calcula el precio y actualiza el detalle y el total.

for (producto <- catalogo) {
  if (producto.disponible) {
    val precioFinal = aplicarDescuento(producto.precio, descuento)
    lineasImperativas += ((producto.nombre, precioFinal))
    totalImperativo += precioFinal
  }
}

Separemos el bucle en tres operaciones

El bucle ya resolvió el problema. Ahora cada operación expresa una decisión y produce un resultado intermedio o final.

filter · Seleccionar

Un predicado devuelve Boolean. Se conservan los productos disponibles.

Lista de productos

map · Transformar

Una función convierte cada producto en una tupla con su nombre y su precio final.

List[LineaCotizacion]

foldLeft · Acumular

La suma empieza en cero. La función combina el total parcial con el precio de cada línea.

Total en BigDecimal

producto => producto.disponible es una lambda. Pasarla como argumento ilustra por qué filter es una operación de orden superior.

Un nombre para cada línea y una función por campaña

Alias de tipo

LineaCotizacion nombra el par (nombre, precioFinal). Las firmas muestran qué representa el dato y la tupla conserva sus dos componentes.

Currificación y aplicación parcial

El método recibe el descuento y los productos en dos listas de parámetros. Al fijar el 10 %, queda una función que espera los productos.

¿Qué cambia al calcular el total con una vista?

Las dos cadenas dan el mismo total. La diferencia está en cuándo se producen las líneas.

List · Evaluación estricta

filter entrega la lista de disponibles. map entrega la lista de líneas. Después, foldLeft consume esas líneas.

El detalle queda listo para mostrarlo y reutilizarlo.

view · Evaluación perezosa

Cuando foldLeft pide cada línea, la vista filtra y transforma según la demanda.

Para calcular solo el total, se recorre la entrada una vez y se evitan las listas intermedias.

Ambas variantes son secuenciales. Si volcamos la vista a una lista para mostrar el detalle, esa lista sí se materializa.

Ampliación · ¿Por qué el promedio es seguro?

En el reto avanzado agrupamos los productos disponibles y calculamos el precio final promedio de cada categoría.

  1. groupBy crea una clave a partir de un producto existente.
  2. crearLineas genera una línea por cada producto del grupo.
  3. El número de líneas de cada grupo es positivo. Si la entrada está vacía, no hay grupos que promediar.

El resultado tiene tipo Map[String, List[Producto]]. Que cada grupo tenga elementos se deduce de cómo se construye.
